## What it is

The game is one HTML page, `dist/index.html`, plus the committed assets copied to `dist/art/`. The build also packages local `dist/vendor/` dependencies/fonts, the service worker and generated offline manifest. `arttools/packed_manifest.json` is authoritative for asset paths, hashes, dimensions and count. GitHub Pages publishes them together. The separate retained Claude artifact preview is older:
- slug `3c61f5cf-5c3e-4ea3-92c3-8f59472dd858`
- https://claude.ai/artifact/8TU29g27SqEknG1MYuJB3u

It is played mostly in the Claude iOS app at roughly 390×720 CSS px with a device pixel ratio of 3. Everything must work by touch on a phone.

There is no framework and no bundler. Plain browser JavaScript modules are written as IIFEs (`const Name = (() => { ... return {...}; })();`) and concatenated in a fixed order. SQL runs in the browser through the locked npm sql.js asm build, copied to `vendor/sql-asm.js`, against a seeded in-memory SQLite database. All runtime fonts and dependencies are same-origin. Title/Hero download and save controls are released; the [offline plan](plans/2026-11-24-offline-play.md) and release history record exact CI/hosted evidence.

## Runtime structure

Verified SQL battle-feedback release ([plan](plans/2026-11-24-sql-battle-feedback.md), [release evidence](RELEASE_HISTORY.md#sql-answer-power-and-battle-comparisons)): `query_feedback.js` supplies escaped battle comparisons, a bounded token-difference view, one verified small correction (or a labelled reference solution), compact/full SQL disclosure and named hint/show power caps. `Engine.grade` supplies result-based `quality`; `game.js` applies it to attack damage separately from skill-based accuracy. Comparisons are temporary encounter state, with no save change. Read-task overlap penalizes missing/extra/duplicate rows; write-task progress subtracts unchanged baseline rows so a no-op earns no power. Existing full-correct contract and lesson gates remain.

- **Game ↔ Scene boundary.** `Scene` (scene_a/b) draws and moves things. It never reads game state directly; it asks the `host` (HOST in game.js) for things like `app()`, `tpls(r)`, `habitat(tpl)`, `mark(e)`, `interact(e)`, and `spawn(tpl)`. The game drives the scene through `Scene.load`, `Scene.FX.*`, `Scene.corpse`, `Scene.remains`, `Scene.emptied`, `Scene.enterHall`, and so on. Keep this boundary: new world behaviour goes in the scene behind a host callback, and new rules go in the game.
- **Entities** are plain objects in `map.ents`. `kind` is one of: mon, npc, folk, banker, boss, corpse, chest, node, home, master, student, dummy, and others. Tapping calls `SH[kind](e)`.
- **UI** is HTML strings rendered into fixed containers:
  - `#sheet`: bottom sheet
  - `#say`: dialogue
  - `#fight`: fight panel
  - `#enc`: exercise
  - `#title`: title and character select
  - `#toast`, `#hud`, `#nav`

  Buttons carry `data-a="action"` plus `data-*` arguments. One delegated listener calls `ACT[a](dataset)`. Every new button is an `ACT` entry.
- **Query keyboard** (`kbDraw`/`kbPress` in game.js, helpers in sqled.js). A bar (Commands, Fields, Format); letter rows; a bottom row 123, ⌨, `,` `*` `'`, space, return, Run (the three symbol keys are hidden on the 123 layer, which has them, and on the phone keyboard); a 123 layer with the full symbol set. The Commands panel opens with a top row `,` `*` `'` and a Symbols ▾ button (`KB.lsym`) that shows the rest of the Symbols group, then only the commands the account has been taught (see 02_GAMEPLAY.md, Learned commands). Both Commands and Fields have a fixed bottom row with Done, `,`, `*`, Return, backspace and Run; newline insertion preserves the open list and editor selection.
- **Curly quotes** are added to displayed text automatically by a MutationObserver. Code, SQL, tables and the editor are skipped.

## Continuous motion and presentation

Manual movement uses fractional visible coordinates with swept body clearance, sliding and immediate steering. Integer tile ownership follows position; resource/step events use travelled distance so rocking across a boundary cannot farm steps. The concealment adapter passes one metered unit to `Sneaking.move` per actual-distance tick; coordinate displacement still detects teleports, independently of rounded tile ownership. Stopping never rewinds the visible actor. Scripted tile paths retain their existing behavior. Hero hair/headgear uses a renderer-owned direction-specific walking-width calibration in running frames; generated anchors/art are unchanged.

Rendered NPC head/silhouette geometry owns name placement (12 CSS px). Actor separation uses ground shadows plus a softened subpixel dark edge after Casey's capture feedback. Actor frame/head/body caches are bounded; creation transforms only needed head cuts rather than whole hair atlases. `previewHuman` renders actual directional avatars. Environment effects draw visible areas only; architecture decoration leaves compiled structural masks authoritative.

The shell includes a standalone manifest, viewport-fit, an opaque status backing and safe-area top padding. Candidate adds authored opaque 180px Apple touch and 192/512px manifest icons, including maskable presentation, through the normal hashed offline asset inventory. Automated phone/WebKit/DPR checks cannot verify the user's physical iPhone Home Screen behavior. The actual-device blur fix remains a reported validation limitation until Casey checks it.

## Coding conventions (learned the hard way)

- **Edit by exact replacement.** Use a Python patch with `assert s.count(old) == 1`, or the Edit tool, so a stale anchor fails loudly instead of patching the wrong place.
- **Never put a `//` comment in the middle of a long line.** Much of game.js has many statements per line, and a mid-line `//` silently disables everything after it. In pass 23 this broke all loot granting. Put comments on their own line or use `/* */`.
- **Keep new numbers in one place**, as named constants near their system (`BLESS_C`, `TRAIN_CAP`, `LOOKC`, `respT`), and mirror them in 02_GAMEPLAY.md.
- **Keep each pass small enough to test.** End with the checks required for its actual scope passing and relevant visual captures opened. Documentation needs no game tests/screenshots. Use the current verified scope-based selection.
- **Don't trust the art packing for scale.** Packed art is normalised to fill its cell. Scale in code (for example `MSC` for creatures) and check against the hero, who is about 65 art px tall (≈ 21.7 world px).
- **Use the units consistently.** World units are 16 px per tile. The canvas draws art at K = 3× sprite resolution: `lw`/`lh` convert hi-res art to world px.
- **Performance target:** 60 fps headless in town. Chunks are painted lazily. Avoid offscreen-canvas composite tricks; one WebKit build showed only the base layer.
- **Scrolling screens must not shrink their children.** `.q-body > *`, `#q-out > *` and `#f-out > *` are `flex-shrink: 0`; a wrapped chip row was once squeezed over the result box. Generic class names are scoped (`li.good`, not `.good`) because `.verdict.good` and `h2.good` picked up the list-row grid.
- **Keep the debug export** (`window.__bw`) available on localhost/file only, and extend it when new systems need tests.
